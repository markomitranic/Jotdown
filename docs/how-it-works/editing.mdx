Every page in the studio is already open for editing. There is no Edit button
and no second screen: you click the sentence that is wrong, fix it, and press
**Save changes** at the foot of the window. Say the deploy guide still names
last year's staging host. You click the hostname, type the new one and save.
A moment later it is a commit on the project's branch, written as you, and
the site picks it up on its next build. In a folder project it is simply the
file on your disk.

What follows is the handful of things you cannot discover by looking: how
blocks are added and moved, what saving does, and what happens when the file
changes somewhere else while you write. Why the editor works the way it does is in
[The browser editor](./browser-editor.mdx).

## Click a word and write

Click anywhere in the article and the caret lands there. Text, headings,
lists, tables, callouts and code blocks all take typing in place, and the
page keeps the house look while you write, because it is the page.

Select words and a menu opens beside them. Its top row names the block and
turns it into another kind, with a preview of each kind as you point at it.
Under it are **Bold**, **Italic**, **Strikethrough**, **Inline code**,
**Link** and **Clear formatting**. Paste a link over a selection to link it. Clicking a link while
editing never follows it; it opens a small card with **Visit**, **Edit** and
**Remove link**.

The markdown you already know works at the start of an empty line:

| Type | You get |
| --- | --- |
| `## `, `### `, `#### ` | A heading. `# ` is a heading 2 too, since the title is the page's only heading 1 |
| `- ` or `1. ` | A bulleted or numbered list. **Tab** and **Shift Tab** indent |
| `> ` | A quote |
| ```` ``` ```` | A code block |
| `---` | A divider |

**⌘ Z** undoes anything on the page, a shortcut included, and **⌘ Shift Z**
redoes it. On Windows and Linux it is **Ctrl**.

## Add a block with `/`

Type `/` on an empty line, or click the `+` that appears in the margin beside
one, and a menu lists every block the page can hold: headings and lists,
diagrams, whiteboards, images, videos, file attachments, tables, the six
callouts from **Note** to **Danger**, and the bigger pieces such as **Steps**,
**Tabs** and **Cards**. A preview of the highlighted block sits beside the
menu. Keep typing to filter it, `/warn` for a warning, and press **Enter**.

**Paste markdown** at the top of the menu takes markdown from your clipboard,
from an agent's reply or another page, and drops it in as real blocks.
[Every block](../examples/every-block.mdx) shows each one as a reader sees it.

## Move, turn or delete a block

Rest the pointer on a block and a grip of six dots appears in the margin.

- **Drag the grip** to move the block. A line shows where it lands, into a
  callout or out of one included.
- **Click the grip** for its menu: **Turn into** another kind (a paragraph
  into a callout, a list into numbered steps), **Insert above** or **below**,
  **Duplicate**, **Copy as markdown** and **Delete**.
- **Drag across several blocks**, or **Shift click** one, to select whole
  blocks. The grip then acts on all of them, and **Delete**, **Tab** and the
  arrow keys work on the selection.

## Pictures and files

Drop an image or a file onto the page, paste a screenshot, or pick **Image**
or **File attachment** from the `/` menu. Images are PNG, JPEG, GIF or WebP;
attachments are PDF, zip, CSV, JSON, text and Office files. An image over
2 MB asks whether to compress it first, which it never does without asking.
A file over 4 MB goes up only once you confirm it, since every clone of the
repository carries it forever, and nothing over 25 MB goes up at all.

An upload is written the moment it lands, before you save the page: its own
commit in a GitHub project, a file in the uploads folder in a folder project.
It is safe even if you walk away. Click an image to replace it or to give it alt
text, the sentence a screen reader says in its place.

## Title, description and icon

The title and the line under it are fields like any other: click and type.
The description is what search and section cards show, so make it one
sentence on what the page answers. Click the icon beside the title to search
the [Lucide](https://lucide.dev/icons/) set for another, or hover the title of
a page without one to add it.

Any other front matter field has no form. Open the page menu in the top
right corner and pick **Edit as Markdown** to change the file as text.

## Save your changes

The bar at the foot of the window counts what you changed, "3 changes", and
offers one button that always says what pressing it does:

<Steps>
  <Step>
    ### Save changes

    Your edits go to the project's branch as one commit, "docs: (studio) update
    Deploying", made with your GitHub token and credited to whoever
    `git config --global` names on your machine. The bar says **Published**.

    Every commit the studio makes starts with `docs: (studio)`, so
    `git log --invert-grep --grep='^docs: (studio)'` leaves only the code's
    history.
  </Step>

  <Step>
    ### Reload the page

    The studio redraws the page from the commit you just made.
  </Step>
</Steps>

Nothing is lost between presses. Every keystroke is kept in this browser, so
you can close the tab, come back tomorrow and find your edits still there,
with a dot beside the page in the sidebar to remind you. **⌘ S** says as much
rather than saving: a commit is always the button.

In a folder project, **Save changes** writes the file to your disk and commits
nothing. The bar says **Saved** and the page reloads on its own, and you review
the change with `git diff` and commit it with the rest of your work.

## When the file changed elsewhere

If the file was written by an agent, your IDE or another machine while you
wrote, the bar says **This page has moved on**. **Reload** brings your edits back on top of their
version, and any edit that no longer fits is listed beside what it would
replace, for you to copy or dismiss.

## Undo a save

Open the page panel with **⌘ 3** and pick **History**. Every commit that
touched the page is there, with who made it and when. Open one to see how it
differs from the page today, then **Load into editor** to bring that version
back as unsaved changes, and save it like any other edit.

<Accordions>
  <Accordion title="Pages you cannot edit">
    A page marked `generated: true`, such as a reference a script writes from
    code, is written by code and says so with a **read-only** badge under its title: change its
    generator instead. A `.md` page, such as a changelog, edits as text but
    hides the blocks only an `.mdx` page can hold, Steps and Tabs among them.
    A hand-drawn figure keeps its grip, so it can be moved, copied or deleted,
    but is not typed into.
  </Accordion>

  <Accordion title="Throwing your changes away">
    The arrow beside the save button opens **Dismiss changes**, which reloads
    the page from the file and forgets every edit you made on it.
  </Accordion>
</Accordions>

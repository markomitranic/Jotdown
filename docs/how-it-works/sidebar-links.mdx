Sometimes the next thing a reader needs is not on this site. The Next.js docs,
a Figma board, the Grafana dashboard the runbook keeps talking about. Until now
the only way to offer one was a link buried in a paragraph, which works right up
until a reader arrives on a different page and never sees it.

Fumadocs has had a spelling for this the whole time. A row in a folder's
`pages` array can be a markdown link instead of a filename, and it draws as an
ordinary sidebar row that happens to leave the site. Nothing here had to be
built to render one. What was built is the other half: the
[browser arranger](./browser-editor.mdx) can now write, move and delete those
rows, so adding one is a form to fill in rather than a hand edit to `meta.json`.

## Adding one without leaving the browser

In the studio, the last row of the sidebar, **Add to the sidebar**, opens a
menu with Link beside Page and Separator, and the `+` on any page carries Link
for one that belongs inside it.

The form asks three things: the words the row says, the address it points at,
and an optional icon out of the same [Lucide](https://lucide.dev/icons/)
catalogue a page's icon comes from. Once it is in, the row behaves like the
others: drag it up and down, drag it into a section, and use its own `⋯` to
edit or remove it, or click its icon to pick another. Nothing is written until
you save, so a link you added and then thought better of is one click on the
undo arrow away.

## Adding one by hand

Type the entry into the folder's `meta.json`, at the place you want the row.
The first line is the one you want almost every time:

| What you type | What you get |
| --- | --- |
| `"[Next.js docs](https://nextjs.org/docs)"` | a row that leaves the site |
| `"[Rocket][Next.js docs](https://nextjs.org/docs)"` | the same, with a Lucide icon |
| `"external:"` in front of either | a full page load instead of an in-app navigation |

The first bracket pair, when there are two, is the icon.

The prefix is the one you can usually forget. Anything carrying `https://` is
treated as off-site already, so `external:` only says anything about an address
starting with `/`, and the only reason to reach for it is an address this
deployment serves without this app building it. Everything else navigates
normally.

## A link is not a page

It has no file behind it, which is most of what there is to know. It is not in
search and not in `/llms.txt`, and `bun run check:links` never looks at it either:
that reads markdown in `docs/`, and this is JSON.

One place it does turn up is a `<DocCardList />` at the level it sits in, where
it draws a card with the row's words and nothing underneath them. A link has
nowhere to keep a `description`, so if a bare card reads badly beside its
neighbours, that is the thing to know before putting one at the top level.

The upside of the same fact is that deleting one costs nothing. There are no
words to lose, no redirect to leave behind and no links to repair, which is why
it is the one row the arranger deletes without asking twice.

<Accordions>
<Accordion title="Why a link has no ops of its own">

Every other structural change is a file operation: a page is written, moved or
deleted, and the endpoint does arithmetic on a corpus of files to work out what
to commit. A link is not in that corpus. The whole of it is one string in one
`pages` array.

So it rides in the op that already rewrites those arrays. When the arranger
sends a folder's order it now names every link in it alongside the filenames,
and that order is the whole truth about that folder's links: one left out of it
is one the reader deleted. Adding, re-pointing, moving and deleting a link are
all the same `reorder`, and the endpoint gained no new case for any of them.

</Accordion>
<Accordion title="Why the arranger drags links but does not offer Move to…">

`Move to…` picks a destination out of a list, and that list includes sections
the tree currently has collapsed. Writing a link into a collapsed folder would
mean writing that folder's whole order from rows the browser is not drawing,
which would drop every other link in it.

Dragging has no such gap, because a row can only be dropped into a section that
is open in front of you. So a link moves by being dragged, and the dialog is not
offered rather than being offered and occasionally wrong.

</Accordion>

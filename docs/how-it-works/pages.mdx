The sidebar is where pages are made and moved. Rest the pointer on it and
every row offers a `+` and a `⋯`; drag a row and it moves. Nothing is
committed while you work: each change waits with a small dot beside it, and
one **Save** at the end turns the lot into a single commit, or a single write
to disk in a folder project. Say you want a Runbooks group with three new pages under Operations. You add the
pages, drag them into place, put a heading over them and save once.

Old addresses keep working. Every move and rename is recorded in
`docs/moved.json` in the same save, so a link a reader bookmarked last week
follows the page to where it went, and links between pages are rewritten for
you. For a section with a sidebar of its own, see
[Sections and the switcher](./sections.mdx).

## Add a page

Pick **Add to the sidebar** at the foot of the tree, or the `+` on a row to
add **inside** it, and choose **Page**. Type its title in the empty row and
press **Enter**. The file is named after the title, lowercase and hyphenated,
so "Restoring a backup" becomes `restoring-a-backup.mdx`.

The new row waits with a dot until you save, and only then can it be opened
and written in. Save as soon as the page is where you want it.

## Drag it where it belongs

Press a row and move it. Up and down picks the gap between rows; left and
right picks how deep it sits, one level per step, and a dashed slot shows
where it will land. Rest it on a closed folder for a moment and the folder
opens.

Drag a row one step to the right under a page to put it **inside** that page.
The page becomes a folder with itself as the landing page, keeping its
address, and grows an arrow to fold its children away.

## Group pages under a heading

A heading over a few pages, without a folder, is a **Separator**. Add one from
**Add to the sidebar**, name it, and drag it above the first page it should
cover. It labels every page below it up to the next separator, and no address
changes. Use a folder instead when the group deserves a landing page of its
own.

**Link** in the same menu adds a row that points at another site. See
[Putting a link in the sidebar](./sidebar-links.mdx).

## Rename, readdress or move

The `⋯` on a row holds the rest:

- **Rename** changes the title in the sidebar and on the page. Double-click
  the label does the same. The address stays.
- **Change URL…** gives the page a new address. The old one redirects.
- **Change icon…** picks a [Lucide](https://lucide.dev/icons/) icon.
- **Move to…** picks a new folder from a list, for when dragging would be a
  long scroll.

## Save the arrangement

A card in the bottom left corner counts what is waiting, "3 unsaved changes",
with an undo arrow for the last one, **Discard** and **Save**. Save writes
everything at once. The waiting changes are kept in this browser, so a reload
does not lose them.

## Delete a page

Deleting is not done from the sidebar. Open the page, press **⌘ 3** for the
page panel, and pick **Delete this page…** under **Page settings**. It asks
twice, then saves straight away. Links to the page across the docs turn
back into plain text in the same save, and its address is recorded as gone.

  <Accordion title="Rows that will not move">
    The home page stays first and cannot be moved or deleted.
    Generated pages, marked `generated: true`, are written by code, so
    neither they nor their folder can be rearranged, and a slot over one turns
    red.
  </Accordion>

  <Accordion title="Moving a page to another section">
    The sidebar only arranges the section you are in, so a page cannot be
    dragged from one section into another. Move the file in git and fix both
    folders' `meta.json`, as
    [Sections and the switcher](./sections.mdx) describes.
  </Accordion>

  </Accordion>

A project's colours are a few lines of plain data in `.jotdown/config.json`. You
pick about nine colours for light mode and nine for dark: the page ground, the
text, the accent, a red for errors and five chart colours. The framework works
out every other shade from those, the card behind a callout, the hairline under
a heading, the grey of a caption. Set `"primary": "#433a86"` and the current
sidebar row, the links, the focus rings and the accent in every figure turn
indigo together.

The names are <abbr title="A popular React component collection. Its colour variables, like --background and --primary, have become a shared vocabulary that many themes and tools use.">shadcn</abbr>'s
own tokens, so a palette from a shadcn theme generator, a VS Code theme or a
terminal scheme maps across almost name for name. A project with no `theme` at
all wears the default palette. Why it is data and not a
stylesheet is in [ADR 0016](../decision-records/0016-theme-in-the-config.mdx).

## Change it from the studio

You rarely type any of this by hand. The gear at the right end of the status
strip, or <kbd>Ctrl</kbd> + <kbd>,</kbd> (<kbd>⌘</kbd> + <kbd>,</kbd> on a Mac), opens the project's settings: every field
of `.jotdown/config.json` as a form, over the whole window.

- **Theme** starts you from a palette, lists every colour of both modes with its
  contrast against the background, and works a dark mode out of the light one
  in a click. **Paste a theme** takes the CSS variables a
  [tweakcn](https://tweakcn.com) or shadcn theme exports, since the names match.
  A typeface picked from Google Fonts is copied into your uploads, so readers
  never fetch it from Google.
- Every change repaints the page at once, before anything is saved. Hold
  **Peek** to see the page behind the settings in the draft, or close them: the
  draft stays on until you save or discard it.
- **Save** writes the config as one commit, like a page. **History** lists every
  commit that changed it, and restoring one puts it back into the draft for
  you to look over and save.

The rest of this page is what those settings write, for when you want to read
the file or an agent edits it.

## Pick the core colours for each mode

Add a `theme` to `.jotdown/config.json` with a `light` and a `dark` object, and set
the core colours in each. This is the framework's own manual, a night sky in
dark mode and the same sky by day:

```json title=".jotdown/config.json"
{
  "theme": {
    "light": {
      "background": "#ffffff",
      "foreground": "#1c1a33",
      "primary": "#433a86",
      "destructive": "#c4321f",
      "chart-1": "#5b45c9",
      "chart-2": "#2f5fc4",
      "chart-3": "#9a5800",
      "chart-4": "#a83c78",
      "chart-5": "#0b7a66"
    },
    "dark": {
      "background": "#0d0c1b",
      "foreground": "#ecebf5",
      "primary": "#b9acff",
      "destructive": "#f2b8b5",
      "chart-1": "#a99cff",
      "chart-2": "#86a6ff",
      "chart-3": "#f0c987",
      "chart-4": "#f2a3cf",
      "chart-5": "#7fdcc4"
    },
    "radius": "0.375rem"
  }
}
```

Each mode stands on its own. A colour you set in `light` never shows up in
dark mode, so a dark theme is never left with a light card. A core colour
you leave out keeps the framework default for that mode, which means you can
start with `primary` alone and add the rest as you go. Leave a whole mode
out and that mode keeps the default palette exactly as it is. `radius` is the corner
rounding, shadcn's `--radius`, in `rem` or `px`.

Pick `primary` and the five chart colours as if they were text, because they
are. `primary` is every link and the current sidebar row, and the chart colours
are the labels inside figures and the 13px current row of a coloured section.
Aim for 4.5:1 against `background`, and against the card colour too, since the
sidebar and callouts sit on the card. That is why light mode above has a dark
amber, `#9a5800`, where dark mode can afford a pale one.

Save the config, and the studio's next page view wears it.

<Accordions>
  <Accordion title="What each core colour paints">
    | Token | Where you see it |
    | --- | --- |
    | `background` | the page ground, and the base every surface is mixed from |
    | `foreground` | body text, headings, and the other half of every mix |
    | `primary` | links, the current sidebar row, focus rings, the accent in figures |
    | `destructive` | delete buttons and errors in the editor |
    | `chart-1` to `chart-3` | the three hues of every figure, and the stripe along the bottom of the window |
    | `chart-4`, `chart-5` | the fourth and fifth series of a chart, and whichever sections you point at them |
  </Accordion>
  <Accordion title="What counts as a colour">
    A value is `#hex` (3 to 8 digits), or one of `rgb()`, `rgba()`, `hsl()`,
    `hsla()`, `oklch()`, `oklab()`, `lab()` and `lch()` with plain numbers
    inside. Named colours like `rebeccapurple`, `var()`, `color-mix()` and
    anything with a `;` or a brace are refused, because the theme is written
    straight into a stylesheet and a value must not be able to end the rule it
    sits in.

    A token name shadcn does not have, `brand` or `link` say, is refused too.
    Either way the config check fails with the field it did not like, and the
    project does not open until it is fixed.
  </Accordion>
</Accordions>

## Set a shade yourself when the mix is wrong

Every token that is not core is mixed from the core ones, and the mix is right
most of the time. When it is not, set that token by name and yours wins. This
site's dark mode wants its callouts a shade bluer than a plain mix gives, and
its focus ring in the moon's cream rather than the accent:

```json title=".jotdown/config.json"
{
  "theme": {
    "dark": {
      "card": "#141229",
      "popover": "#1a1834",
      "ring": "#e9d9a6"
    }
  }
}
```

The derived tokens chain, so setting one moves the ones built on it. Set
`card` and the sidebar and popovers follow; set `border` and the input outlines
follow. Look up what a token is made of before you override it, below.

<Accordions>
  <Accordion title="Every derived token and what it is mixed from">
    A percentage is how much `foreground` is mixed into `background`, in
    <abbr title="A colour space where equal steps look like equal changes in lightness to the eye, so a 6% mix looks equally subtle on a light and a dark ground.">oklab</abbr>.

    | Token | When you leave it out |
    | --- | --- |
    | `card` | 3% |
    | `popover` | `card` |
    | `secondary`, `muted` | 6% |
    | `accent` | 8% |
    | `border` | 13% |
    | `input` | `border` |
    | `muted-foreground` | 66% |
    | `ring` | `primary` |
    | `primary-foreground`, `destructive-foreground` | `background` |
    | `card-foreground`, `popover-foreground`, `secondary-foreground`, `accent-foreground` | `foreground` |
    | `sidebar` | `card` |
    | `sidebar-foreground`, `sidebar-accent-foreground` | `foreground` |
    | `sidebar-primary` | `primary` |
    | `sidebar-primary-foreground` | `primary-foreground` |
    | `sidebar-accent` | `accent` |
    | `sidebar-border` | `border` |
    | `sidebar-ring` | `ring` |

    The framework also mixes a few shades of its own that are not shadcn
    tokens and cannot be set: headings in `foreground`, soft ink at 78%,
    hairlines from `border`, and the wash behind the current row at 10%
    `primary`.
  </Accordion>
</Accordions>

## Give each section its colour

A [section](../how-it-works/sections.mdx), a folder with a sidebar of its own, tints its
icon and its current row with a colour of its own. Name the colour by its
token in `theme.sections`, keyed by the folder:

```json title=".jotdown/config.json"
{
  "theme": {
    "sections": {
      "manual": "chart-4",
      "guides": "chart-1",
      "journal": "chart-3"
    }
  }
}
```

A token has a value in each mode, so one line covers both, and the section
already clears the contrast you checked for the chart colours. A section
without an entry wears `primary`, and the main tree always does.

## Set the icon and logo

Both are uploads, named by their public address:

```json title=".jotdown/config.json"
{
  "logo": { "alt": "Notes", "src": "/uploads/icon.png", "srcDark": "/uploads/icon-dark.png" },
  "favicon": "/uploads/icon.png"
}
```

`favicon` is the project's icon: the browser tab, the top of the sidebar, the
switcher and the app. It is always drawn in a square, so a square image of about
512 px reads best, and the settings fit whatever you upload into one. The
`logo` is an optional wide wordmark for places that fit one. A project with no
`favicon` has its logo fitted into the square instead, so an old wide logo
shrinks rather than pushing the title aside. `srcDark` is optional, for a logo
that disappears on a dark ground. The setup wizard writes both from the icon you
drop on it.

## Pick the typefaces

The theme's `fonts` sets the three faces a site reads in: `sans` for running
text and the interface, `serif` for the odd display title, and `mono` for code.
Each names a family, and the file to load it from when a reader's machine will
not have it, a variable font among the uploads:

```json title=".jotdown/config.json"
"theme": {
  "fonts": {
    "sans": { "family": "Geist", "src": "/uploads/fonts/geist.woff2" },
    "mono": { "family": "JetBrains Mono" }
  }
}
```

A family you name without a file has to be installed where it is read, so keep
that to the system's own faces. A face you leave out keeps the framework's:
Inter, the system serif and JetBrains Mono.

That is the whole of a project's look. There is no stylesheet beside the
theme, so nothing a page or a site carries can restyle the blocks out from
under the editor. A rule only one site wants belongs in a component of its own.

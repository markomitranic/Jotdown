Jotdown is an app on your Mac. You download it once, keep it in the Dock, and
every project you work on sits in one switcher, the folders on your disk beside
your GitHub repositories. Say Claude Code has just written
`docs/checkout/refunds.mdx` in a folder: you open it in Jotdown, read the page
the way the site will show it, fix the one sentence it got wrong, and commit
when you are happy with `git diff`.

A folder saves straight to disk and commits nothing. A GitHub project saves as
one commit on its branch, in your name; see
[The browser editor](../how-it-works/browser-editor.mdx). Either way, an open
page refreshes when its file changes on disk or the branch moves on, so an
agent or another machine never leaves you reading a stale copy.

## Install it

<Steps>
  <Step>
    ### Download the DMG

    Open the [latest release](https://github.com/markomitranic/Jotdown/releases/latest)
    and download `Jotdown-<version>.dmg`. It is built for Apple Silicon Macs.
  </Step>

  <Step>
    ### Drag it into Applications

    Open the DMG and drag **Jotdown** onto **Applications**, then eject the DMG.
  </Step>

  <Step>
    ### Open it the first time

    Jotdown is not signed with an Apple Developer ID yet, so the first launch
    is refused with "Apple could not verify Jotdown". Open **System Settings**,
    then **Privacy & Security**, scroll to the message about Jotdown and click
    **Open Anyway**. macOS asks once more, and never again for this version.
  </Step>
</Steps>

## Sign in to GitHub

Click **Sign in to GitHub** in the top right of the welcome page. Jotdown shows
a short code; **Copy code and open GitHub** opens github.com in your browser,
where you paste it and approve. The window notices on its own, and your GitHub
projects appear in the switcher.

The token GitHub hands over is kept in your macOS Keychain. **Sign out** in the
same corner forgets it. Folders open without signing in at all.

## Add a project

Press **⌘ 2** for the switcher and pick **Add a project**:

- **A GitHub repository.** Every repository you can reach that holds a
  `.jotdown/config.json` is listed. Paste `owner/repo` or its address for
  anything the list missed.
- **A folder on this Mac.** **Add a local project** opens the folder picker.
  A folder holding a `.jotdown/config.json` opens as a project, and keeps its
  address, `/local/<folder name>`, for as long as it is in your list.
- **Something new.** A folder or repository with no config yet is a job for
  the [setup wizard](./setting-up-a-project.mdx): **Set up a new project** in
  the same switcher.

Saving to a folder writes the file and stops there: review it with `git diff`
and commit it with the rest of your change. When an agent rewrites a page you
have open, the page refreshes on its own, and a save over its words is
refused and offers a reload instead.

## The strip along the bottom

Everything above the strip at the foot of the window is your project, in its
own look. The strip is Jotdown's, and it answers "where am I, and what can the
app do from here?":

- **The project.** Its name, and whether it lives on GitHub or on this Mac.
  A click opens the switcher, like **⌘ 2**.
- **The branch.** The branch you read and edit. For a GitHub project, picking
  another one moves where the app reads and commits, and nothing in the
  repository changes. For a folder, it checks the branch out with git, which
  refuses while uncommitted changes are in the way and says why.
- **Reload.** Reads the project again from GitHub or the folder, and checks
  for a newer Jotdown on the way.
- **VS Code.** For a folder, opens it in VS Code at the page you are on.
- **The renderer.** Whether the page is drawn by the project's site, a dev
  server or the app itself; see [your own blocks](../publication/own-blocks.mdx).

The empty stretch of the strip drags the window, like a title bar.

## Ask your agent for a first page

Paste this into Claude Code, Codex or Cursor at the root of a repository the
setup wizard made into a project. Pull first if the wizard committed to
GitHub, so the skills it wrote are on your disk.

```text title="Prompt"
Read the authoring, blocks and figure skills in .agents/skills/ first. Find
one thing in this codebase that is architecturally important but hard to
explain: a flow across several modules, a non-obvious invariant, or a
decision a newcomer would get wrong. Give me three candidates, one line each
with the files involved, and wait for my pick.

Then write the page under docs/architecture/ in the content folder
.jotdown/config.json names, per the authoring skill: one question it
answers, an abstract, and at least one figure that explains the mechanism.
Ground every claim in the code and name the files. Skip the editorial
illustration for now. In your reply, not on the page, list anything you
could not verify.

Run `jotdown check` on the page and fix every error it reports. Don't commit.
Tell me the path of the page you wrote.
```

Pick one of the three, and the page appears under **Architecture** in
Jotdown. Fix what it got wrong, then commit it yourself.

## Run it from a checkout

Working on Jotdown itself, you run the same studio from a checkout, with Bun
1.4.2:

```sh
git clone https://github.com/markomitranic/Jotdown.git
cd Jotdown
bun install --frozen-lockfile
bun run dev
```

It opens at `http://localhost:6192` and signs in the same way. Set
`STUDIO_DEV_TOKEN="$(gh auth token)"` to skip the sign-in and use the token the
<abbr title="GitHub's command-line tool, which keeps a signed-in token for you">gh</abbr>
CLI holds. `bun run build` in `apps/desktop` builds the app and its DMG into
`apps/desktop/artifacts`.

  <Accordion title="Who the editor is">
    The editor is whoever `git config --global` names, and that name goes on
    every commit a GitHub save makes. Page history is the project's own git
    log, and empty for a file git ignores.
  </Accordion>

  <Accordion title="Where it keeps things">
    Your list of projects is `favorites.json` in
    `~/Library/Application Support/com.markomitranic.jotdown/stable`, beside
    the studio's log and its cache of GitHub projects. The GitHub token is in
    the Keychain. Nothing is written into your repository except the pages you
    save. Run from a checkout, the list lives in `~/.config/jotdown` instead.
  </Accordion>

  <Accordion title="Keeping it current">
    The app checks for a newer release every ten minutes and downloads it in
    the background, and **Reload** on the strip checks at once. Once it is
    ready, **Restart to update** shows on the strip, in the welcome page's top
    right and at the bottom of the project switcher, and a click installs it
    and opens the app again. That is apart
    from the `jotdown` ref a project pins in its config for its
    [site](../publication/publishing.mdx).
  </Accordion>
</Accordions>

A repository becomes a Jotdown project the moment it has a
`.jotdown/config.json` on its default branch, and a folder the moment it has
one on disk. The setup wizard writes that file, the first pages, the agent
skills, a note in `AGENTS.md` and, if you ask, the host files for a
[site](../publication/publishing.mdx). For a GitHub repository all of it
lands as one commit on the default branch. For a folder on your disk the files
are written in place, and the folder is bookmarked in the switcher.

Say you are adding docs to `you/site`, a monorepo whose apps live under
`apps/`. You open the wizard, pick the repository, put the docs in
`apps/docs`, keep the starter pages and skills, choose Vercel for later, and
press Create. A minute later there is one commit on `main` with every file
listed, and the project opens in the studio.

## Before you start

Jotdown reaches GitHub as the account you signed in with (see
[Installing the app](./local-studio.mdx)), and you need write access to the
repository. A folder on your disk needs nothing.

## Run the wizard

Open the switcher with **⌘ 2** (**Ctrl 2**), choose **Add a project**, then
**Set up a new project**. A repository without docs offers the same wizard on
its own page.

<Steps>
<Step>

### Repository

**GitHub repository** or **Folder on this computer**. Pick a repository from
the list or paste `owner/repo`; for a folder, type its path. The wizard checks
straight away that the studio can see it and that you can commit to it.

</Step>
<Step>

### Content folder

Where `docs/` goes, uploads included: the repository root, or a folder such as
`apps/docs` in a monorepo. The config always stays at the root and points
at it with `content`. Files already in the way can be moved into `_old/` for
an agent to port later.

</Step>
<Step>

### Name

A title, a one-line description and, optionally, the public address of the
site. All of it is [configuration](../how-it-works/configuration.mdx) you can
change later.

</Step>
<Step>

### Look

A starting palette and a square icon, with a light and a dark preview of the
sidebar that follow your pick. See [Branding](./branding.mdx) for everything
past that.

</Step>
<Step>

### Pages

A starter set, Getting started, Architecture and Decision records with a first
record, or just a home page. Either is a placeholder for your agent to replace.

</Step>
<Step>

### Agents

**Install skills** copies the docs skills into `.agents/skills/` and links them
into `.claude/skills/`. **Tell agents where the docs are** adds a short
Documentation section to `AGENTS.md`, or creates it with a `CLAUDE.md` that
imports it. Both are on by default, and both are explained in
[Connecting your agents](../context-warehouse/connecting-agents.mdx).

</Step>
<Step>

### Publishing

**Not yet**, **GitHub Pages** or **Vercel**. A host adds its files, the
workflow under `.github/workflows/` or `vercel.json` in `.jotdown/`, and the
config pins the Jotdown version; the rest is in
[Publishing it as a site](../publication/publishing.mdx).

</Step>
<Step>

### Review and create

Every file the wizard will write, move or delete is listed before anything
happens, and nothing already there is overwritten. A repository gets one
commit straight on its default branch. For a folder the files are written in
place and nothing is committed, so you review them with `git diff` and commit
them yourself.

</Step>
</Steps>

## What lands in the repository

```
you/site/
├── AGENTS.md                ← a Documentation section, appended
├── CLAUDE.md                ← @AGENTS.md, only when neither file existed
├── .agents/skills/          ← the docs skills
├── .claude/skills/          ← a symlink per skill file
├── .jotdown/
│   ├── config.json          ← version, title, content, theme, repository…
│   └── vercel.json …        ← only when you picked a host
└── apps/docs/
    └── docs/                ← index.mdx, meta.json, the starter sections
        └── _uploads/        ← icon.png, when you dropped an icon
```

## Or set it up by hand

The wizard is a convenience; the project is just these files. At the root:

```json title=".jotdown/config.json"
{
  "version": 1,
  "title": "Site",
  "content": "apps/docs"
}
```

Then a home page at `apps/docs/docs/index.mdx`, with `title` and `description`
front matter, and an `apps/docs/docs/meta.json` with `"pages": ["index", "..."]`.
Commit both to the default branch, or add the folder from the switcher with
**Add a local project**. The skills and the `AGENTS.md` section are in
[Connecting your agents](../context-warehouse/connecting-agents.mdx).

<Accordions>
  <Accordion title="The project does not show up in the switcher">
    The studio reads `.jotdown/config.json` from the default branch only, and
    the token it runs with needs access to the repository. Pasting
    `owner/repo` into the switcher opens it directly.
  </Accordion>
  <Accordion title="Editing a branch other than the default">
    Set `branch` in the config on the default branch, and the studio reads and
    saves to that branch instead.
  </Accordion>
</Accordions>

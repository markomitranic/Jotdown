GitHub Pages serves a static site straight from the repository it belongs to,
so the docs, the build and the address all live in one place. Add one workflow
file, turn Pages on, and push. From then on every push to
`main` publishes, and so does every studio save to the project. This page
assumes the steps in [Publishing it as a site](./publishing.mdx) up to the host.

## Add the workflow

From Jotdown's [`deployment/github-pages`](https://github.com/markomitranic/Jotdown/tree/main/deployment/github-pages)
folder, copy `.github/workflows/jotdown.yml` and `.jotdown/.gitignore` into the
same places in the content repository. The setup wizard writes both when you
pick GitHub Pages as the host.

The workflow clones Jotdown at the version the config pins, runs its build
script, and hands `.jotdown/out` to Pages. A fix to the build reaches you with
the next Jotdown version you pin, never through this file. It publishes on
pushes to `main`; change the branch in the file if yours is another.

## Turn it on

<Steps>
<Step>

### Name the address

A project site lives at `https://<owner>.github.io/<repository>`, below the
domain's root, so set `url` in `.jotdown/config.json` to exactly that. The
build reads the path from it and writes every link, upload and script under
it. With a custom domain, `url` is the domain and the path is empty.

</Step>
<Step>

### Turn on Pages

In the repository's **Settings**, then **Pages**, set **Source** to
**GitHub Actions**.

</Step>
<Step>

### Push

The **Actions** tab shows the build. When it finishes, the deploy step names
the site's address.

</Step>
</Steps>

<Accordions>
  <Accordion title="Why a page address works without .html">
    The build writes `/onboarding/first-week` as `onboarding/first-week.html`.
    GitHub Pages answers an address with no extension from the `.html` file of
    the same name, so links stay clean without a rewrite rule.
  </Accordion>
</Accordions>

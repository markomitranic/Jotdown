An agent writes a page in a minute, and it reads well whether it is right or
not. So read it the way a reader will, in the studio, before it is
committed. Say you asked Claude to document how refunds flow through
checkout. It writes `docs/checkout/refunds.mdx` on your disk, you open it in
the studio, find it names a queue that was renamed in spring, fix that one
word in place and commit the page with your change.

Two moments to catch it: before it is committed, which is the easy one, and
after it has landed on the branch. How agents find and write pages in the
first place is in [Connecting your agents](./connecting-agents.mdx).

## Before it is committed

<Steps>
  <Step>
    ### Open the folder in the studio

    Open Jotdown and add the repository the agent worked in as a local
    project: **⌘ 2**, then **Add a project** and **Add a local project**. The
    studio opens the folder as it is on disk, uncommitted pages included. See
    [Installing the app](../studio/local-studio.mdx) to get it.
  </Step>

  <Step>
    ### Read it as a reader

    Open the page from the sidebar. Agents keep working while you read, and
    when one rewrites the page you have open, it refreshes on its own within
    about ten seconds.
  </Step>

  <Step>
    ### Fix it in place

    Click the wrong sentence and correct it, as in
    [Editing a page](../how-it-works/editing.mdx). **Save changes** writes the file and
    commits nothing.
  </Step>

  <Step>
    ### Commit it yourself

    `git diff` shows the agent's page and your fixes together. Commit them with
    the code change the page describes.
  </Step>
</Steps>

## What to check

Agents get the shape right and the facts wrong. Spend your attention on what
only somebody who knows the code can see:

- **Names.** Every file, function, queue, flag and environment variable the
  page names exists, under that name, today.
- **Claims.** A sentence that says what the system does, "retries three
  times", "runs nightly", is true in the code, not in a plausible world.
- **The question.** The title answers something a reader would ask, and the
  page stops when the answer is given.
- **Figures.** A diagram shows the system as it is, with no box the code does
  not have.
- **Links.** Each one opens the page it names.
- **Secrets.** No token, password or connection string came along from a
  config file the agent read.

Ask the agent to list what it could not verify, in its reply rather than on
the page, and start with that list. The
[first-page prompt](../studio/local-studio.mdx#ask-your-agent-for-a-first-page) does
this already.

## After it has landed

When the agent committed and pushed, the studio picks the page up within a
minute. Open it and press **⌘ 3** for the page panel, then
**History**. Each commit that touched the page is listed with its author; an
agent's commit names the agent, from the `Co-authored-by` line its tool
writes.

Fix what is wrong and save, which is a commit of its own on top. To take the
page back to an earlier version, open that version in **History** and press
**Load into editor**, then save.

## When the page will not open

An agent's slip shows up where the reader would hit it, with what to fix:

- **"This page could not be compiled."** The page holds something a page may
  not, usually an `import`, a script or a `{expression}`. The red line under it
  names which. Pages hold markdown and the [built-in blocks](../examples/every-block.mdx)
  only; ask the agent to read the blocks skill and try again.
- **"This page cannot open because its front matter is broken."** The fields
  at the top of the file do not read. A form underneath offers **Title**,
  **Description** and **Icon**; fill them in and **Save and open**.
- **"A file in this project could not be read."** A banner on every page,
  usually for a `meta.json` the agent edited. **Fix** opens it.
- **"The block could not be drawn."** One block failed and the rest of the
  page is fine. It names the file and line.
